KEY IMPLEMENTATION DETAILS
================================================================================

RETRY TRACKING:
- Max attempts: 5 (configurable via const in ProcessBatchAsync)
- Attempt counter: Incremented for every broadcast attempt
- Error tracking: Last error message stored (max 2000 chars)
- Last attempt time: Recorded for each retry

DEAD-LETTER LOGIC:
1. After failed broadcast:
   - If attempt_count < 5: Record error, continue retrying
   - If attempt_count >= 5: Set dead_lettered_at_utc, stop retrying
   
2. Special cases:
   - Malformed JSON: Immediately dead-letter (no retries)
   - Connection lost: Retry (transient)
   - HTTP timeout: Retry (transient)
   - Other exceptions: Retry up to max attempts

INDEX OPTIMIZATION:
- Old: "processed_at_utc IS NULL" (includes stuck messages)
- New: "processed_at_utc IS NULL AND dead_lettered_at_utc IS NULL"
- Effect: Database automatically prunes dead-lettered rows from index
- Performance: Faster queries as table grows

DATABASE COLUMNS:
- attempt_count INTEGER NOT NULL DEFAULT 0
- last_attempt_at_utc TIMESTAMP WITH TIME ZONE
- last_error VARCHAR(2000)
- dead_lettered_at_utc TIMESTAMP WITH TIME ZONE
